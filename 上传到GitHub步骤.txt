存存 CUN CUN · GitHub 上传与后续维护说明
========================================

【现状】2026-11-21 已经推上去了
  仓库：https://github.com/zmy531/cuncun （Public，main 分支）
  内容：源码 + 图标 + README + LICENSE + 4 张截图 + cuncun-1.5.1.apk
  本地仓库就在：桌面\cuncun（已经是 git 仓库，remote 已配好）
  所以下面的「一、二」是首次上传时的流程，留着备查；以后只要做「四、以后改完代码怎么更新」。


一、在 GitHub 建仓库（已经建好了，仅供参考）
------------------------------------------
1. 打开 https://github.com/new
2. Repository name 填：cuncun
3. 选 Public（想私有就选 Private）
4. "Add a README / .gitignore / license" 全部不要勾
5. 点 Create repository


二、首次推送（已经完成，仅供参考）
----------------------------------
在桌面\cuncun 里右键 →「在终端中打开」，然后：

   git init -b main
   git add .
   git commit -m "存存 CUN CUN 1.5.1"
   git remote add origin https://github.com/zmy531/cuncun.git
   git push -u origin main

如果远端已经有 README（网页上建仓时勾过），会提示要先合并：
   git fetch origin
   git merge -s ours --allow-unrelated-histories --no-edit origin/main
   git push -u origin main

推送要登录：浏览器弹授权窗口点同意即可。要用户名密码时，密码填 Personal Access Token
（GitHub → 头像 → Settings → Developer settings → Personal access tokens → Tokens(classic)
→ Generate new token，勾 repo 权限，复制那串字符当密码）。


三、把 APK 挂到 Releases（建议做一次）
--------------------------------------
1. 仓库页面右侧 → Releases → Create a new release
2. Tag 填：v1.5.1
3. Title 填：存存 1.5.1
4. 说明里贴 README 的「版本历史」那一段
5. 把 cuncun-1.5.1.apk 拖进 Attach binaries
6. Publish release

README 里的下载链接指向 Releases，挂上去之后点开就能下。


四、以后改完代码怎么更新
------------------------
   git add .
   git commit -m "改了什么"
   git push

本机直连 GitHub 有时会 Connection reset，走本地代理再推就行（已经在这个仓库里配过一条）：
   git config http.proxy http://127.0.0.1:7897    # 端口按你代理软件实际的改
   git push
   git config --unset http.proxy                  # 不想留就撤掉

版本号要同时改三个地方（不然覆盖安装会失败）：
   AndroidManifest.xml 的 android:versionCode / android:versionName
   build.ps1 的 $apkName、--version-code、--version-name
   MainActivity.java 里 Bridge.info() 的 version 字符串


五、几点提醒
------------
- .gitignore 已排除 build/、*.jks、*.idsig。签名密钥（cuncun.jks）千万别上传，
  别人拿到就能签出和你一样的包。
- build.ps1 里是本地自用口令（cuncun2026），公开仓库里建议改成从环境变量读取。
- 截图在 screenshots/，README 已按文件名引用，换图同名覆盖即可。
- 仓库里的数据全是虚构示例（138 0013 8000 / demo@example.com），别把自己真实的
  手机号、密码、身份信息提交进这个文件夹，尤其别把 seed.js 换成自己的真实导出。
